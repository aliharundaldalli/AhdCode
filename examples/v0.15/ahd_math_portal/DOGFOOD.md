# v0.16 dogfood findings

Measured against the completed v0.15 reference application on 2026-09-05. Counts are literal call sites in application source, excluding comments, helpers' definitions, temporary probes, and framework sources unless stated. These are scoped usability findings, not a proposal to change v0.15 during this task.

| Severity | Concrete evidence | Consequence and focused next step |
| --- | --- | --- |
| MAJOR | 27 handler calls to `sessionOpen`, 26 to `contextFor`, and 76 response branches wrapped in `sessionCommit`. | Request/session lifecycle plumbing is easy to miss on early returns. v0.16 should make session-aware request context and response finalization a supported composition pattern. |
| MAJOR | All 12 POST handlers call `csrfValid`; forms also have to carry their own hidden input. The initial navbar omitted its logout token and ordinary logout failed. | A first-party CSRF-aware form helper should couple token rendering and verification. The application fix passes the existing session through layouts and renders the field; protection was not relaxed. |
| MAJOR | 30 `request.form` reads, 12 `errors.add` calls, and four hand-written account/auth view functions (`loginView`, `registerView`, `forgotPasswordView`, `resetPasswordView`) carry old fields/errors explicitly. | Add small typed form readers, reusable validation results, and safe old-input/error rendering. Keep password fields excluded. Existing generic trimming also applies to passwords; email shape and schema length validation remain basic. |
| MAJOR | 15 `adminGuard` call sites repeat the guard/refusal/commit branch. Uploads separately resolve the user and refuse anonymous requests. | Support reusable authentication/authorization guards without hiding the handler's policy. Never infer admin status from UI or submitted role fields. |
| MINOR | 13 `flashSet` calls and 12 `Web.redirect` calls across page handlers; three layouts each handle flash rendering. | Provide a documented POST/redirect/flash pattern and one-time consumption rules. It should compose with explicit validation failures and preserve safe old input. |
| MAJOR | Five repositories issue 27 query/execute calls and make 31 row conversion helper calls. Four shared helpers map NULL/missing columns to empty/zero values. | Typed result access and clearer nullable conversions would reduce repetition and expose missing-column mistakes instead of silently defaulting. Keep parameter binding explicit. |
| MAJOR | Four database mutation paths in password reset: create, consume, change password, invalidate other tokens. Consumption and password change are separate statements. | Document/support a transactional reset pattern, with expiry rechecked atomically at consumption. Current expected valid/expired/used/wrong-verifier cases pass; multi-token concurrency and partial DB failure are not a transactional guarantee. |
| MINOR | One upload adapter must sniff type, check size, check duplicate, save under a generated name, insert a row, and clean up the newly saved file on failure. `solutionsCreate` catches all `MySQLError` values as a duplicate outcome. | Improve structured storage/database error results and an explicit cleanup pattern. Preserve the database UNIQUE constraint as the final one-time authority. No new upload product features are needed. |
| MINOR | One SMTP adapter uses client/auth/message/send; one catch returns false and its caller ignores delivery failure. `SMTP_FROM_NAME` has an accessor but is not applied. | Document safe mail configuration, STARTTLS versus implicit TLS, display-name composition, and private delivery diagnostics. Keep the public forgot-password response generic. The local 587/implicit-TLS mismatch was caught by a handshake-only probe. |
| MAJOR | Gemini uses one HTTP request builder and a parser that walks six nullable JSON lookups plus type/array-length guards before splitting labelled text. | A safe JSON path/typed decoding helper and reusable HTTP error mapping would simplify this adapter while keeping model text escaped and publication explicit. No Gemini-specific framework is needed. |
| MAJOR | The admin setup entry point initially imported Database without App configuration, so a valid local `.env` still produced `MySQL username must not be empty`. | Make runtime configuration initialization for multiple entry points explicit and hard to omit. The app fix imports Config/App before opening MySQL. |
| MINOR | The canonical Web URL cannot include a public port; `SERVER_PORT` is the internal bind port, and APP_HOST forbids ports. Local TLS on an unprivileged 8443 needed one application-specific `APP_PUBLIC_PORT` helper. | v0.16 should distinguish public origin from internal socket, with validated optional public port and clear proxy examples. |
| INFO | `.test` is advertised as a development identity but no resolver is installed. Trying to open the advertised hostname confused this project's user. | State the limitation at the point of use and offer an explicit, opt-in local hostname/TLS setup. Do not silently edit hosts or trust stores. |
| INFO | 213 `Web.UI` calls, three layouts, six components, 45 `.ahd` source files. Bootstrap 5.3.3 is served locally. The standalone binary works without compiler/framework source access. | The existing semantic UI/require/native runtime foundations work for this portal; preserve those contracts. |

No released-compiler blocker remains for the requested acceptance. Application fixes during continuation were limited to configuration initialization, the missing logout CSRF field and its layout plumbing, and the optional public-port helper requested for local HTTPS. The framework, compiler, and release refs were not changed.

## What should v0.16 actually solve?

Prioritize request/session finalization; CSRF-aware forms with validation, errors and safe old input; composable guards; nullable database/JSON access; and clear public-origin/local-TLS configuration. Then document transactional password reset and structured upload/mail failures. These needs came directly from repeated code and observed failures in this application. Avoid an ORM rewrite, frontend toolchain, or unrelated portal features.
